# Design Spec: WebUI Studio Interface Redesign (Modern Unified Studio)

- **Date**: 2026-10-11
- **Target Plugin**: `astrbot_plugin_openai_image`
- **Scope**: Studio WebUI frontend (`pages/studio/index.html`, `pages/studio/style.css`, `pages/studio/app.js`) and corresponding i18n (`.astrbot-plugin/i18n/zh-CN.json`).

## 1. 概述与设计目标
将 `astrbot_plugin_openai_image` 内置 WebUI 的生图与编辑工作台，从旧版左右分栏的表单预览布局重构为图2所呈现的现代居中卡片式创作工作台。
核心目标包括：
1. **统一创作入口**：将原有的「生图」与「编辑」标签页合并为统一的「创作」主工作台。
2. **智能模式流转**：无参考图时自动执行文生图；点击左上角上传参考图后自动流转为图片编辑（图生图）。
3. **结果置顶展示**：根据用户确认，将生成进度与结果画布展示在居中创作卡片的正上方，创作卡片常驻于下方，便于连续微调与迭代。
4. **高保真还原图2控件**：
   - 居中标题与环境光晕背景；
   - 带有精致外发光的悬浮创作卡片；
   - 左上角 `[🖼️ 图片]` 参考图入口；
   - 自适应提示词输入框（支持快捷键触发）；
   - 底部左侧快捷比例/尺寸与张数选择器；
   - 底部右侧提示词自动优化滑动开关、高级设置微调、圆形主发送按钮 `[↑]`；
   - 底部居中轻量免责文案。

## 2. 界面与组件结构设计

### 2.1 顶部导航
- 保留右上角「刷新」按钮。
- 导航标签精简为 3 项：
  - `[创作]`（默认高亮激活）
  - `[历史图库]`（保留原有搜索、分类筛选、分页与预览图库）
  - `[设置]`（保留原有提示词优化模型参数配置）

### 2.2 居中创作区域（Studio Panel）
- 容器采用居中流式布局，最大宽度限制为 860px。
- **未生成态（初始待机）**：
  - 居中大标题：`欢迎体验图像创作，今天想创作什么？`
  - 悬浮创作卡片（Border-radius: 20px，细边框 + 微环境发光）。
  - 卡片内部构成：
    - **左上角参考图区域**：`[🖼️ 图片]` 按钮，支持多图选择，已上传图片展示为微型胶囊缩略图，悬停可删除。
    - **中央输入框**：无边框多行自适应文本框，占位符为 `输入你的图像创作想法`。支持 `Ctrl/Cmd + Enter` 或直接 `Enter` 触发生成，`Shift + Enter` 换行。
    - **底部工具栏**：
      - 左侧：`[📐 自动 ⌄]` 尺寸下拉选择（支持常用预设与自定义分辨率）、`[🗂️ 1张 ⌄]` 数量选择（1~4 张）。
      - 右侧：`[⚙️]` 高级参数快捷弹窗（调节质量与审核等级）、`[提示词优化 开关]`（现代滑动开关）、`[↑]` 圆形主发送按钮（空内容时置灰禁用，生成中变为加载动画）。
  - 卡片下方居中文案：`所有内容均由人工智能模型生成，仅供参考，非官方立场`。

### 2.3 结果展示区域（位于创作卡片正上方）
- 当发起任务或存在生成记录时，在创作卡片上方动态平滑展开：
  - **加载态**：微光骨架屏与实时状态（如 `正在优化提示词...`、`正在调用模型生成...`）。
  - **结果卡片网格**：
    - 高清大图呈现；
    - 卡片悬停操作项：查看原图（全屏光箱缩放）、下载、作为参考图继续编辑（一键回填到下方创作卡片）、复制提示词。
  - **异常态**：友好的错误提示与重试按钮，保留下方输入内容不丢失。

## 3. 数据流与交互规范

1. **提交校验与优化流**：
   - 校验提示词是否非空。
   - 若勾选「提示词自动优化」，前端先调用 `POST /{PLUGIN_NAME}/optimize-prompt` 进行扩写，状态显示为优化中。
2. **生图/编辑自动分流**：
   - 若存在参考图：打包为 `FormData`，发送至 `POST /{PLUGIN_NAME}/edit`。
   - 若无参考图：打包为 JSON，发送至 `POST /{PLUGIN_NAME}/generate`。
3. **完成处理**：
   - 将返回图片渲染到上方结果区域。
   - 后台静默刷新图库数据，确保切换至「历史图库」时数据完全同步。

## 4. 异常处理与兼容性保证
- 保持所有后端已有 API 完全向后兼容，不破坏现有 CLI 命令与核心逻辑。
- 完善深色/浅色主题适配，使用现有 CSS 变量体系。
